- F8 Filament rewards staff/Gate enforcement in handlers — see
  `slice-f8.md`. Key discoveries recorded there:
  - Filament 5.8 `Action::isDisabled()` folds in `isHidden()`, so
    `mountAction()`/`callMountedAction()` refuse a hidden action;
    `callTableAction()` also asserts visibility. A Gate-denied record action
    is unreachable through the normal Livewire test helpers, so the handler
    boundary must be probed by invoking the configured action closure
    directly (`$table->getAction($n)->record($r)->data($d)->call()`).
  - The program create form's owner `Select` already rejects unresolvable
    owner aliases / missing records via its option-label lookup, so those two
    plan "reds" are contract guards, not reds; the real FR-5 red is that the
    handler passed the config alias verbatim, so the UI could not create an
    owned program at all.
  - Spatie teams are enabled and the team resolver is
    `OwnerContextTeamResolver`, so rebinding `OwnerResolverInterface` changes
    the permission team and silently drops a user's team-scoped roles.
  - A new test file was needed for the Gate-denial cases because
    `RewardAdminAdaptTest.php` registers a blanket `Gate::before(fn () => true)`
    (Laravel evaluates before-callbacks first-non-null-wins, so no denial can
    be expressed there).

- F9 core program update — see `slice-f9.md`. Key decisions recorded there:
  - Extracted `ReferralProgramAttributeNormalizer` from
    `CreateReferralProgram::handle()` so create and update share one rule set
    (the root cause was inline-only normalization, so the admin edit path could
    not reuse it).
  - `UpdateReferralProgram` merges the stored values under the payload using
    the model's **casts** (`$program->referrer_reward` is an array,
    `$program->starts_at` is a `CarbonImmutable`) — `getAttributes()`/`only()`
    would hand the normalizer raw JSON strings.
  - Slug rule: merged like any attribute, but when the payload supplies `name`
    and no `slug` the merged slug is dropped so it re-derives from the name
    exactly as creation would. Without that, a name-only edit could never
    produce the plan's "empty-slug name" rejection; without the merge, an
    unrelated partial edit would silently rewrite a customised slug.
  - The plan asked for `InvalidArgumentException` → `ValidationException`, but
    Filament's `assertHasFormErrors()` resolves keys against the schema state
    path (`data.<field>`), so the error must be attached to a real field.
    Solved with `ReferralProgramAttributeException extends InvalidArgumentException`
    carrying the attribute name (matches the repo's existing convention in
    `affiliates`/`pricing`).
  - `Select::disabled()` does **not** stop dehydration — the status field needs
    both `->disabled(fn ($operation) => $operation === 'edit')` and
    `->dehydrated(fn ($operation) => $operation !== 'edit')`. Field closures can
    inject `string $operation` (`Component::resolveDefaultClosureDependencyForEvaluationByName`),
    and Filament sets it via `defaultForm()` (`operation('create'|'edit')`).
  - `OwnerWriteGuard` throws `AuthorizationException` (not
    `ModelNotFoundException`) when a row exists but belongs to another owner.

## Conventions that keep costing time

- BSD `grep` on this machine does not support `\|` alternation — use the
  Grep tool or `grep -E`.
- Pest file-scope helper functions must be uniquely named across the whole
  suite (they are global once a file loads).
- The base `AIArmada\Commerce\Tests\TestCase::defineDatabaseMigrations()`
  already loads `packages/vouchers/database/migrations`; the referrals suite
  needs no extra harness for the voucher rail.
- `HasOwner::assertOwnerMatchesCurrentContext()` requires a program's owner
  tuple to match the active owner context, so owned-record tests must reuse
  the harness default owner (`OwnerContext::resolve()`).
- `TransitionRewardAwardAction` prohibits caller own-approval, so award
  decision tests need a staff actor distinct from the recipient.
