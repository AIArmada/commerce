# Affiliate Network Audit

## Packages Reviewed (bullets)
- `packages/affiliate-network` (`aiarmada/affiliate-network`) — multi-merchant network: sites, offers, categories, creatives, applications, links, catalog import, verification strategies
- `packages/filament-affiliate-network` (`aiarmada/filament-affiliate-network`) — Filament v5 admin: offer/site/category/application resources, marketplace + merchant-dashboard pages, widgets

## Overall Assessment (quality, health, risks, refactor size)
- Quality: moderate. Clean strategy/contract seams (`SiteVerificationStrategyInterface`, `CatalogReaderInterface`), UUID PKs, `getTable()` from config, `CarbonImmutable` usage, signed redirect route. Small surface (6 models, 9 migrations, 5 actions, 4 services).
- Health: functional but leaky. Only 2/6 models use first-class `HasOwner`; the other 4 use package-local `ScopesByAffiliateOwner`/`ScopesBySiteOwner` traits that reimplement global-scope semantics with `whereHas` subqueries. Filament pages sprinkle `withoutOwnerScope()` with global-context fallbacks — correct only if every call site is intentional.
- Risks: (1) two overlapping affiliate vocabularies — `affiliates.Affiliate/Program/Link/Creative` vs `affiliate-network.AffiliateSite/AffiliateOffer/AffiliateOfferLink/AffiliateOfferCreative` — with a `LocalProgramReader` bridging them and no documented boundary; (2) relation-traversal scopes (`whereHas('affiliate')`/`whereHas('site')`) on every query of 4 models; (3) `TrackNetworkLinkCookie` + signed redirect + `OfferLinkService` TTL logic split across 3 files.
- Refactor size: S–M (1–3 days). Boundary doc + scope consolidation + Filament scoping audit; no schema redesign.

## Migration Impact
**Migration Required: NO**
- Tables/columns: no renames or type changes. 9 migrations (`affiliate_network_sites`, `offer_categories`, `offers`, `offer_creatives`, `offer_applications`, `offer_links` + 3 additive `*_source` columns) all use `uuid('id')->primary()`.
- Indexes/constraints: no FK constraints/cascades in migrations (verified) — compliant. No constraint changes recommended.
- Data migration: none. Scope-trait consolidation is query-layer only; stored `owner_type/owner_id` columns on sites/categories unchanged.

- Core owns: site lifecycle + verification (`Services/SiteVerificationService.php`, `Strategies/DnsVerificationStrategy.php`, `FileVerificationStrategy.php`, `MetaTagVerificationStrategy.php`, `Support/DnsRecordResolver.php`, `Support/SiteContentFetcher.php`), offer management (`Services/OfferManagementService.php`, `Actions/CreateOffer.php`, `UpdateOffer.php`, `ApproveApplication.php`, `ApplyToOffer.php`), link minting/redirect (`Services/OfferLinkService.php`, `Http/Controllers/LinkRedirectController.php`, `Http/Middleware/TrackNetworkLinkCookie.php`), catalog sync (`Services/OfferImportService.php`, `Services/Catalog/LocalProgramReader.php`, `RemoteCatalogClient.php`), conversion recording (`Actions/RecordNetworkConversion.php`, `Listeners/RecordNetworkConversionForOrder.php`, `Events/NetworkConversionRecorded.php`).
- Filament adapter owns: 4 resources + tables/forms, `AffiliateMarketplacePage`, `MerchantDashboardPage`, `NetworkStatsWidget`, `TopOffersWidget`, `AffiliateNetworkOptionsProvider`, `NetworkStatsAggregator`, `NetworkAdminAccess`, policies, plugin/provider.

## Architecture Findings (each: Severity Critical/High/Medium/Low, Location files, Problem, Why It Matters, Recommended Fix concrete, Breaking Change YES/NO, Affected Packages list, Required Dependent Changes, Migration Required YES/NO)
1. Severity: High. Location: `packages/affiliate-network/src/Models/AffiliateOffer.php` (uses `ScopesBySiteOwner`), `AffiliateOfferLink.php` + `AffiliateOfferApplication.php` (use `ScopesByAffiliateOwner`), `AffiliateOfferCreative.php` (no owner trait at all — re-check 2026-09-07: only `HasUuids` + `HasFactory` + `HasCommerceAudit`, confirmed), vs `AffiliateSite.php`/`AffiliateOfferCategory.php` (first-class `HasOwner` + `HasOwnerScopeConfig` with `affiliate-network.owner` key). Problem: three different ownership mechanisms in one 6-model package; creatives have no scoping whatsoever. Re-check 2026-09-07: migration `000004` carries no owner columns (only `offer_id` + `offer_id/is_active` index), so scope-via-offer is the only migration-free option — finding confirmed, kept at High. Why It Matters: inconsistent isolation guarantees; `whereHas`-based scopes are N+1-prone and bypass-phrased (`withoutGlobalScope('owner_via_affiliate')` string literal in `OfferLinkService.php:116` — confirmed). Recommended Fix: give `AffiliateOfferCreative` an owner path (scope via its offer→site chain using the same `ScopesBySiteOwner` mechanism — no migration needed per the verified migration shape), and replace both `ScopesBy*` traits' hand-rolled `OwnerContext::resolve()` + `assertResolvedOrExplicitGlobal()` blocks with commerce-support's `OwnerScope` semantics (keep the relation-traversal but delegate predicate construction to a shared helper). Breaking Change: NO (query behavior preserved). Affected Packages: `filament-affiliate-network` (its `withoutOwnerScope()` call sites assume current scope names). Required Dependent Changes: update string-literal scope references to class-based (`ScopesByAffiliateOwner::class` or scope class). Migration Required: NO.
2. Severity: High. Location: `packages/affiliates/src/Models/Affiliate.php`, `AffiliateProgram.php`, `AffiliateProgramCreative.php`, `AffiliateLink.php` vs `packages/affiliate-network/src/Models/AffiliateSite.php`, `AffiliateOffer.php`, `AffiliateOfferCreative.php`, `AffiliateOfferLink.php`, plus bridge `packages/affiliate-network/src/Services/Catalog/LocalProgramReader.php` (verified exists) and `Services/OfferManagementService.php`, resolving core identity via `packages/affiliates/src/Contracts/AffiliateLookup.php` (`Resolvers/DatabaseAffiliateLookup.php`). Problem: unclear boundary between single-merchant programs and multi-merchant network offers. Both have creatives, links, applications/memberships with near-identical lifecycles (`OfferStatus` vs `ProgramStatus`, `ApplicationStatus` vs `MembershipStatus`). Why It Matters: consumers cannot tell whether to create an `AffiliateProgram` or an `AffiliateOffer`; `LocalProgramReader` suggests offers mirror programs but the sync direction/authority is undocumented. Re-check 2026-09-07: boundary direction cross-checked with affiliates audit (affiliates = merchant-local execution via `AffiliateLookup`/`VoucherBridge`; network = discovery/marketplace) — both files now agree (same contract paths, same read-only-reader fix direction). Recommended Fix: document and enforce: `affiliates` = merchant-local program execution (attribution, commissions, payouts); `affiliate-network` = cross-merchant discovery/marketplace (sites publish offers, affiliates apply, links redirect). Make `LocalProgramReader` read-only (network imports program catalog for display; all commission execution stays in `affiliates`). Delete any network-side commission/payout duplication if found (none found at this depth — confirm `OfferManagementService` holds no payout logic). Breaking Change: NO (docs + read-only enforcement). Affected Packages: `affiliates`, `filament-affiliates`, `filament-affiliate-network`. Required Dependent Changes: marketplace page must link to core program enrollment, not duplicate it. Migration Required: NO.
3. Severity: Medium. Location: `packages/affiliate-network/src/Services/OfferLinkService.php:116-122` (`OwnerContext::withOwner(null, ... withoutGlobalScope('owner_via_affiliate') ...)` + `withoutOwnerScope()` on `affiliate`/`site` relations). Problem: public redirect path runs in explicit-global context and strips scoping to resolve any affiliate's link. Why It Matters: correct for a signed public redirect, but the global-context window must be minimal and auditable. Recommended Fix: keep the pattern but narrow it: resolve the link by code inside the global window, then re-enter the link owner's context (`OwnerContext::withOwner($link->affiliate->owner, ...)`) for attribution writes; add a code comment naming this intentional. Breaking Change: NO. Affected Packages: `affiliates` (attribution write). Required Dependent Changes: none. Migration Required: NO.
4. Severity: Low. Location: `packages/affiliate-network/src/Services/Catalog/LocalProgramReader.php`, `RemoteCatalogClient.php`, `CatalogReaderInterface.php`, `Services/OfferImportService.php`, `Console/Commands/SyncSiteOffersCommand.php`. Problem: two catalog readers + import service + sync command for a 6-model package — reasonable but the `catalog_source`/`source`/`rate_source` additive columns (migrations `000007–000009`) suggest source-precedence logic that lives partly in readers. Why It Matters: source precedence bugs cause offer data flapping on sync. Recommended Fix: centralize source-precedence in `OfferImportService` (single `resolveField(source, local, remote)` helper); readers return raw payloads only. Breaking Change: NO. Affected Packages: none. Required Dependent Changes: none. Migration Required: NO.

Confirm `MerchantDashboardPage` aggregates are re-scoped per merchant; `AffiliateMarketplacePage:72-74` `withoutOwnerScope()` is correct for a public marketplace only if the page is authorization-gated (`NetworkAdminAccess` exists — verify it gates these pages). ## Model / Domain Findings
- `AffiliateSite` + `AffiliateOfferCategory` are the only true tenant roots (`HasOwner`, `affiliate-network.owner` key). Everything else hangs off them — correct hierarchy, wrong mechanism (custom traits instead of shared scope helper).

## Recommended Refactor Plan (ordered steps)
1. Fix `AffiliateOfferCreative` scoping gap (trait + tests).
2. Deduplicate `ScopesBy*` traits into one parameterized trait; replace string scope names with class references.
3. Narrow the explicit-global windows in `OfferLinkService` + `ApplyToOffer` (re-enter owner context for writes).
4. Swap filament composer dep to core `affiliates`; remove `config()` fallback literals.
5. Audit `MerchantDashboardPage` aggregates for tenant leakage; gate marketplace pages via `NetworkAdminAccess`.
6. Centralize catalog source-precedence in `OfferImportService`.
7. Write boundary doc (`docs/01-overview.md` + affiliates `docs/07-programs.md` cross-link) + Pest suite.

## Final Recommended Architecture
- `affiliate-network` = marketplace/discovery bounded context (sites, offers, applications, redirect links) reading core affiliate identity via `AffiliateLookup`; all commission execution stays in `affiliates`. Single parameterized owner-via-relation scope; no scoping gaps.
- `filament-affiliate-network` = thin admin over network models only; depends on core `affiliates`, not on sibling Filament package.
