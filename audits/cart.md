# Cart Audit
## Packages Reviewed (bullets)
- `packages/cart` (`aiarmada/cart`) — core domain: `src/` (~110 files), `config/cart.php`, `database/migrations/2000_02_01_000001..000002`, `src/CartServiceProvider.php`, `docs/01..10 + 99`, `CONTEXT.md`, `README.md`, `composer.json`
- `packages/filament-cart` (`aiarmada/filament-cart`) — Filament adapter: `src/Resources|Pages|Widgets|Services|Actions|Models|Jobs|Listeners`, `config/filament-cart.php`, `database/migrations/2000_08_01_000001..000003` (snapshots), `database/factories/*`, `database/seeders/CartSeeder.php`, `src/FilamentCartServiceProvider.php`, `src/FilamentCartPlugin.php`, `docs/01..10 + 99`

## Overall Assessment (quality, health, risks, refactor size)
- Quality: Core `cart` is the strongest of the four pairs. Money-in-minor-units, `HasCartOwner`/`CartOwnerScope` delegating to `commerce-support`, `DatabaseStorage` with owner-scoped query builder, fail-fast owner checks, Octane-safe `ConditionPresets`, and `CONCURRENTLY` index work show senior authorship. Health is good but the pair is over-surfaced: two storage models (live `carts` + filament `cart_snapshots*`), two command paths for abandonment, two condition-action layers, and three target/preset facades for one DSL.
- Health risks: (1) dual-write snapshot divergence (live cart vs `cart_snapshots*` via event listeners), (2) currency fallback split (`MYR` in core vs `USD` fallbacks in 12+ filament/core sites) causing wrong display/rounding, (3) `owner_type`/`owner_id` in `$fillable` allowing owner reassignment, (4) zero tests (`tests/` missing in both packages) for checkout-critical money code, (5) global `cart()` helper + `Cart` facade alias collision surface.
- Refactor size: Medium. No table rebuild needed. Work is deletion + consolidation (remove one storage interface, one example factory, harden fillables, unify currency default, collapse filament condition services into core, make snapshot a read-projection or delete it). Estimated ~15–20 files touched, ~6 files deleted, no data migration.

## Migration Impact
**Migration Required: NO**
- Tables: `carts`, `conditions` (core, `config('cart.database.table'|'conditions_table')`), `cart_snapshots`, `cart_snapshot_items`, `cart_snapshot_conditions` (filament). No table/column rename, no type change, no index drop, no constraint add recommended in this audit.
- Columns: no add/drop required. Optional hardening (remove `owner_type`/`owner_id` from `$fillable`) is application-code only, no schema change.
- Indexes/constraints: no `constrained()`/`cascadeOnDelete()` found — compliant. `CONCURRENTLY` indexes in `2000_02_01_000001` already handle the hot path; hardcoded `carts_*` index names ignore custom table names but fixing is a migration-code fix for future installs, not a migration for existing installs (rename only in new code path, guarded by `IF NOT EXISTS`).
- Data migration: none. Snapshot divergence is fixed by code (single-writer or projection rebuild via `SyncNormalizedCartJob`/`CartSyncManager::sync`), not by backfill. If snapshots are deleted as a direction, that would become a future `dropIfExists` migration — explicitly not recommended here without product sign-off.

## Package Responsibilities
- `cart` owns: cart lifecycle (identifier/instance/version/ttl), items/conditions/metadata persistence via `Storage/DatabaseStorage.php`, totals math (`Traits/CalculatesTotals.php`, `Models/Traits/MoneyTrait.php`, `Conditions/CartCondition.php`, `Conditions/PercentageRate.php`), condition pipeline (`Conditions/Pipeline/*`, `Services/BuiltInRulesFactory.php`, `Services/CartConditionResolver.php`), guest→user migration (`Actions/MigrateGuestCartToUserAction.php`, `Actions/MigrateCartOnLoginAction.php`, `Services/CartMigrationService.php`, `Services/CartMergeStrategyRegistry.php`), owner scoping (`Models/Concerns/HasCartOwner.php`, `Support/CartOwnerScope.php`), events (`Events/*`), validation (`Models/Traits/ValidationTrait.php`).
- `filament-cart` should own only: `Resources/CartResource.php`, `Resources/CartItemResource.php`, `Resources/ConditionResource.php`, `Pages/CartDashboard.php`, `Pages/LiveDashboardPage.php`, `Widgets/*`, tables/forms/infolists. Currently also owns snapshot persistence (`Models/Cart.php`, `Models/CartItem.php`, `Models/CartCondition.php`, `Models/Condition.php`), sync engine (`Services/NormalizedCartSynchronizer.php`, `Services/CartSyncManager.php`, `Services/CartInstanceManager.php`, `Jobs/SyncNormalizedCartJob.php`, `Listeners/SyncCartOnEvent.php`), condition application (`Actions/ApplyConditionToCartAction.php`, `Services/CartConditionValidator.php`, `Services/CartConditionBatchRemoval.php`, `Services/OwnerActionGuard.php`), abandonment (`Commands/MarkAbandonedCartsCommand.php`, `Events/CartAbandoned.php`, `Listeners/SendCartAbandonedNotification.php`), global-condition injection (`Listeners/ApplyGlobalConditions.php`). All of the latter belong in `cart` or should be deleted.

## Final Recommended Architecture
- `cart` becomes the sole domain owner: live persistence (`DatabaseStorage` + `CartModel`), snapshot projection (`Snapshots/CartSnapshot*` + `Snapshots/CartSnapshotSynchronizer`), stored-condition actions (`Actions/ApplyStoredCondition`, `Actions/ValidateStoredCondition`, `Actions/RemoveStoredConditions`), single abandonment command, single `StorageInterface`, single `Target` factory, single currency source (`cart.money.default_currency`, default `MYR`), request-scoped bindings with Octane flush.
- `filament-cart` becomes a true thin adapter: plugin + service provider (config/views only, no `config()->set()` mutation, no `RulesFactoryInterface` binding), three resources + two pages + three widgets + UI-shell actions only. Reads live `CartModel` or core snapshot projection; writes go through core actions with `OwnerWriteGuard`. `queue_sync=true` by default with `SyncNormalizedCartJob` (`OwnerScopedJob`) as the async path.
- Consumers (`checkout`, `affiliates`, `cashier`, `events`, `vouchers`) depend only on `cart` contracts (`CartManagerInterface`, `StorageInterface`, `ConditionProviderInterface`, `RulesFactoryInterface`, cart events). No consumer imports `FilamentCart\*`.
